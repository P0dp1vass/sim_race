# VAR-03 — Шаблон экспертного правила

## Поля правила

| Поле | Назначение |
|---|---|
| `rule_id` | Уникальный идентификатор правила. |
| `symptom_condition` | Описание проблемы в поведении автомобиля, по которому выполняется поиск правила (сопоставляется с `symptom` из запроса). |
| `parameter` | Параметр настройки автомобиля. |
| `direction` | Направление изменения параметра (`increase` / `decrease`). |
| `change_description` | Описание изменения параметра. |
| `expected_effect` | Ожидаемый эффект изменения. |
| `limitations` | Ограничения применения правила. |
| `applicability` | Контекст, в котором правило допустимо применять (например, автомобиль и тип трассы); не используется как описание симптома. |
| `status` | Внутренний статус проверки правила, включая признак «разрешено к выдаче». Пользователю не передаётся. |
| `basis` | Технический источник, обосновывающий рекомендацию. Передаётся в ответе API согласно KIR-02. |

## Шаблон

```json
{
  "rule_id": "",
  "symptom_condition": "",
  "parameter": "",
  "direction": "",
  "change_description": "",
  "expected_effect": "",
  "limitations": "",
  "applicability": "",
  "status": "",
  "basis": ""
}
```

## Соответствие KIR-02

В ответе `POST /api/v1/recommendations` при совпадении используются поля `rule_id`, `parameter`, `direction`, `change_description`, `expected_effect`, `limitations`, `basis`. Название параметра должно соответствовать VAR-02.

Сопоставление выполняется по ключевым словам/подстрокам в `symptom_condition` с текстом запроса `symptom`. В ответ включаются только правила со статусом «разрешено к выдаче»; само поле `status` в ответ не включается. Поле `basis` включается в ответ согласно KIR-02. Если подходящих разрешённых правил нет, возвращается `no_match`.
