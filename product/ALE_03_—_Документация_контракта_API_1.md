# ALE-03 — Документация контракта API

Oct 15, 2026 · @Alena

## Обзор

**Версия 2 от 15.10.** По итогам обсуждения с Кириллом запрос рекомендации стал структурированным (6 полей, комментарий обязателен), а форма обратной связи — внутренней, с новым эндпоинтом. Документ описывает эту версию; Кирилл переносит её в KIR-02 и OpenAPI `openapi/setup-recommendation-service.yaml`.&#32;

У сервиса три эндпоинта. У запроса рекомендации четыре исхода, и каждому соответствует одно состояние интерфейса (EGO-02).

| Эндпоинт | Зачем |
| --- | --- |
| `GET /health` | Проверить, что сервис запущен. Ответ `200 {"status": "ok"}` |
| `POST /api/v1/recommendations` | Принять жалобу пилота и вернуть рекомендации по разрешённым правилам |
| `POST /api/v1/feedback` | **Новый.** Сохранить отзыв пилота о применённой рекомендации (ALE-04) |

**Исходы `POST /api/v1/recommendations` и состояния UI**

| HTTP | `status` | Что значит | Состояние UI | Ветка сценария ALE-01 |
| --- | --- | --- | --- | --- |
| 200 | `match` | Найдено хотя бы одно разрешённое правило | Карточки рекомендаций (EGO-03) | шаг 5 |
| 200 | `no_match` | Подходящего проверенного правила нет | Текст из `message` + подсказка переформулировать | ветка B |
| 400 | `error` | Запрос не прошёл валидацию | Ошибка у незаполненного поля (по \`error.fields\`) | ветка A |
| 500 | `error` | Внутренняя ошибка сервиса | «Повторите позже», жалоба сохраняется | ветка C |

Различать `match` и `no_match` нужно по полю `status`, а не по HTTP-коду: оба приходят с кодом 200.

## Запрос

Запрос состоит из шести полей: пять выбираются из списка, одно — комментарий своими словами. Правило ищется по полям со списками, поэтому поиск не зависит от того, какими словами пилот описал проблему.

`POST /api/v1/recommendations` · `Content-Type: application/json`

| Поле | Тип | Обязательно | Значения | Участвует в поиске |
| --- | --- | --- | --- | --- |
| `car` | string, enum | да | машина из FED-02; в MVP одно значение, форма подставляет его сама | да, с `applicability` |
| `track` | string, enum | да | овал из списка FED-02 | да, с `applicability` |
| `symptom_type` | string, enum | да | `understeer` — недостаточная поворачиваемость (tight), `oversteer` — избыточная (loose) | да |
| `corner_phase` | string, enum | да | `entry` — вход, `mid` — середина, `exit` — выход | да |
| `stint_moment` | string, enum | нет | `from_start` — сразу, `after_laps` — по ходу стинта | да, если передано |
| `comment` | string, 3–500 символов | **да** | проблема своими словами | нет; сохраняется, чтобы команда понимала реальную проблему |

```json
{
  "car": "<машина из FED-02>",
  "track": "<овал из FED-02>",
  "symptom_type": "oversteer",
  "corner_phase": "exit",
  "stint_moment": "after_laps",
  "comment": "После 5 кругов зад срывает на выходе из 3–4, приходится раньше сбрасывать газ"
}
```

**Как сервис ищет правило.** Значения `symptom_type`, `corner_phase` и `stint_moment` сравниваются с такими же полями правила, `car` и `track` — с `applicability`. Участвуют только правила со статусом «разрешено к выдаче». Для этого в шаблоне VAR-03 нужны структурированные поля условия — см. открытые вопросы.

**Для формы (EGO-01):** тип, фаза и момент стинта — кнопки или списки с понятными пилоту подписями («зад срывает / лузит», «мордой мимо / тайтит»). Комментарий проверяется на длину 3–500 до отправки.

## Ответы

### 200 — найдено совпадение (`match`)

| Поле | Тип | Обязательно | Что в нём | Показывать пилоту |
| --- | --- | --- | --- | --- |
| `status` | string, `"match"` | да | Исход | нет |
| `request_id` | string (UUID) | да | **Новое.** ID сохранённого запроса | нет; нужен для отзыва и ссылки на форму |
| `recommendations` | array, не меньше 1 элемента | да | Список рекомендаций | каждая — отдельная карточка |
| `…rule_id` | string, например `R-001` | да | ID правила в SQLite | нет; передаётся в форму обратной связи |
| `…parameter` | string | да | Каноническое имя параметра из словаря VAR-02 | да, заголовок карточки |
| `…direction` | string, enum `increase` / `decrease` | да | Направление изменения (значения зафиксированы в VAR-03) | да, «увеличить / уменьшить» |
| `…change_description` | string | да | Что и на сколько изменить | да, основной текст |
| `…expected_effect` | string | да | Что должно измениться в поведении машины | да |
| `…limitations` | string | да | Когда не применять и чем рискуешь | да |
| `…basis` | string | да | Основание правила, технический источник | на решение команды |

```json
{
  "status": "match",
  "request_id": "6f1c2a9e-3b7d-4c11-9a0e-2d5b8f7c4e10",
  "recommendations": [
    {
      "rule_id": "R-001",
      "parameter": "давление задних шин",
      "direction": "decrease",
      "change_description": "Снизить давление в задних шинах на 1–2 psi",
      "expected_effect": "Увеличение пятна контакта задней оси, снижение избыточной поворачиваемости на выходе из поворота",
      "limitations": "Не снижать ниже рекомендованного производителем минимума",
      "basis": "VAR-01 / проверено FED-05"
    }
  ]
}
```

### 200 — совпадений нет (`no_match`)

| Поле | Тип | Что в нём |
| --- | --- | --- |
| `status` | string, `"no_match"` | Исход |
| `request_id` | string (UUID) | ID сохранённого запроса: ненайденные жалобы — кандидаты в новые правила |
| `message` | string | Текст для пилота, показывать как есть |

```json
{
  "status": "no_match",
  "request_id": "0a8d4e21-7c5f-4b3e-8e19-6b2f1d9c3a77",
  "message": "Подходящее правило не найдено. Попробуйте описать жалобу точнее."
}
```

Backend обязан вернуть `no_match`, а не выдуманную рекомендацию.

### 400 — ошибка валидации и 500 — внутренняя ошибка

| Поле | Тип | 400 | 500 |
| --- | --- | --- | --- |
| `status` | string | `"error"` | `"error"` |
| `error.code` | string | `validation_error` | `internal_error` |
| `error.message` | string | что не так с запросом | «повторите позже» |
| `error.fields` | object `{поле: причина}` | есть | нет |

```json
{
  "status": "error",
  "error": {
    "code": "validation_error",
    "message": "Проверьте заполнение полей",
    "fields": {
      "corner_phase": "обязательное поле",
      "comment": "должен содержать от 3 до 500 символов"
    }
  }
}
```

```json
{
  "status": "error",
  "error": {
    "code": "internal_error",
    "message": "Внутренняя ошибка сервера, попробуйте повторить запрос позже"
  }
}
```

## Обратная связь: POST /api/v1/feedback

Новый эндпоинт для внутренней формы ALE-04. Один отзыв — одна рекомендация из ответа. `request_id` и `rule_id` frontend подставляет сам, пилот их не вводит.

| Поле | Тип | Обязательно | Значения / вопрос формы |
| --- | --- | --- | --- |
| `request_id` | string (UUID) | да | из ответа `recommendations` |
| `rule_id` | string | да | должен быть среди рекомендаций этого запроса |
| `applied` | enum | да | Q1: `as_written` / `other_value` / `not_applied` |
| `applied_value` | string, до 200 | если `other_value` | Q1: на какое значение изменил |
| `not_applied_reason` | enum | если `not_applied` | `unclear` / `no_trust` / `at_limit` / `no_time` / `other` |
| `symptom_result` | enum | если применял | Q2: `gone` / `weaker` / `same` / `stronger` |
| `new_problem` | boolean | если применял | Q3 |
| `new_problem_text` | string, до 500 | если `new_problem = true` | Q3: какая |
| `keep_change` | enum | если применял | Q4: `yes` / `reverted` / `undecided` |
| `clarity` | integer 1–5 | да | Q5 |
| `unclear_text` | string, до 500 | нет | Q6 |
| `same_conditions` | enum | нет | Q7: `yes` / `no` / `unknown` |
| `conditions_diff` | string, до 500 | нет | Q7: чем отличались |

**Ответы:** `201` — `{"status": "ok", "feedback_id": "…"}`; `400` `validation_error` — не заполнено обязательное поле, неизвестный `request_id` или `rule_id` не из этого запроса; `500` `internal_error`. Формат ошибок — как у `recommendations`.

Для этого эндпоинта в SQLite нужны две таблицы: `requests` (поля запроса, `comment`, исход, список `rule_id`, время) и `feedback`. Это меняет пункт «Вне границ MVP» в KIR-01.

## Открытые вопросы к KIR-02

Первые три вопроса блокируют реализацию поиска и обратной связи. Вопрос про значения `direction` закрыт: VAR-03 фиксирует `increase` / `decrease`.

| № | Вопрос | Почему важно | Кому | Предложение |
| --- | --- | --- | --- | --- |
| 1 | Добавить в шаблон правила VAR-03 структурированные поля условия | Сейчас в VAR-03 условие — один текст `symptom_condition` с поиском по подстрокам. Структурированный запрос не с чем сравнивать | Вардгес, Кирилл | Поля `symptom_type`, `corner_phase`, `stint_moment` (пусто = любой) с теми же значениями, что в запросе. В `applicability` — список машин и трасс. В `status` — закрытый список значений |
| 2 | Храним запросы и отзывы в SQLite | Без этого нет `request_id`, комментарии пилотов некуда сохранить, а KIR-01 сейчас исключает историю запросов | Кирилл, Родион | Таблицы `requests` и `feedback`, без персональных данных |
| 3 | Как пилот вернётся к форме после заезда | Авторизации нет: закроет вкладку — потеряет рекомендацию и форму | Егор, Кирилл | Ссылка вида `/feedback/{request_id}?rule_id=R-001` в карточке + последний запрос в localStorage. Нужен `GET` запроса по ID или данные в ссылке |
| 4 | Валидация должна вернуть 400, а FastAPI по умолчанию отвечает 422 с другим телом | Иначе тесты и frontend разойдутся с контрактом | Родион | Свой `exception_handler` → 400 в формате контракта, для обоих POST |
| 5 | Сколько рекомендаций максимум и в каком порядке? | Под одно сочетание может подойти несколько правил | Кирилл, Родион | Не больше 3; сначала правила, у которых совпал и `stint_moment` |
| 6 | Показывать ли `basis` пилоту? | Доверие к совету важно, но там технический источник | Команда | Показывать «Проверено экспертом» |
| 7 | В `change_description` — клики или единицы (psi, %)? | Пилоты мыслят кликами в гараже | Фёдор, Вардгес | Единицы из VAR-02, плюс число кликов, где оно известно |
| 8 | Базовый URL и CORS для frontend | Без CORS браузер не пропустит запрос | Родион, Егор | Разрешить origin frontend в FastAPI |

**Что изменилось по сравнению с KIR-02 v1.** Вместо одного поля `symptom` — шесть полей, `comment` обязателен. Поиск по структурированным полям, а не по подстрокам. В ответах появился `request_id`, добавлен эндпоинт `POST /api/v1/feedback`.
