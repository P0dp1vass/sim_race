# ALE-02 — Критерии приёмки MVP

Oct 15, 2026 · @Alena

## Что значит «MVP работает»

MVP принят, когда пилот через интерфейс отправляет жалобу и получает один из трёх понятных исходов: рекомендацию по проверенному правилу, честное «не найдено» или ошибку с подсказкой. Непроверенное правило не попадает в ответ ни при каких условиях.

**Релиз спринта принимается, если:**

1. Все критерии с приоритетом Must выполнены (таблица ниже).
2. pytest из ROD-05 запущен, результат записан, упавших тестов нет.
3. Сквозная проверка EGO-05 через интерфейс пройдена для трёх исходов, критичных дефектов нет.

**Источники:** контракт API версии 2 (ALE-03, решение с Кириллом от 15.10), архитектура MVP (KIR-01), шаблон правила (VAR-03), сценарий (ALE-01), форма обратной связи (ALE-04). Запрос рекомендации — 6 полей с обязательным комментарием, отзыв — через `POST /api/v1/feedback`.

## Критерии приёмки

17 критериев: 14 Must, 3 Should. Каждый проверяется автотестом (ROD-05), сквозной проверкой через UI (EGO-05) или ручной сверкой данных.

| ID | Приоритет | Условие (дано / когда) | Ожидаемый результат | Как проверяем |
| --- | --- | --- | --- | --- |
| AC-01 | Must | Сервис запущен; GET /health | 200, `{"status": "ok"}` | ROD-05 |
| AC-02 | Must | Есть разрешённое правило; в запросе его `symptom_type`, `corner_phase`, а `car` и `track` входят в его `applicability` | 200, `status: match`, есть `request_id`, в `recommendations` хотя бы одна запись со всеми 7 полями | ROD-05 |
| AC-03 | Must | Ни одно разрешённое правило не подходит под сочетание полей | 200, `status: no_match`, есть `request_id` и `message`, нет `recommendations` | ROD-05 |
| AC-04 | Must | Под сочетание подходит только правило со статусом «не проверено» | `status: no_match`; его `rule_id` в ответе нет | ROD-05 |
| AC-05 | Must | Нет обязательного поля; значение не из списка (`symptom_type`, `corner_phase`, `stint_moment`, `car`, `track`); `comment` короче 3 или длиннее 500 | **400** (не 422), `validation_error`, в `error.fields` каждое ошибочное поле | ROD-05 |
| AC-06 | Must | Внутренняя ошибка (например, недоступна база) | 500, `internal_error`, без трейсбека в теле | ROD-05 |
| AC-07 | Must | Пилот не выбрал трассу, тип или фазу или комментарий короче 3 / длиннее 500 символов | Запрос не отправляется, пустые поля подсвечены. Машина подставлена сразу | EGO-05 |
| AC-08 | Must | Запрос отправлен, ответа ещё нет | Видна загрузка, кнопка неактивна, повторной отправки нет | EGO-05 |
| AC-09 | Must | Ответ `match` | На каждую рекомендацию карточка: параметр, изменение, эффект, ограничения; порядок как в ответе | EGO-05 |
| AC-10 | Must | Ответ `no_match`, 400 или 500 | `no_match`: текст из `message`; 400: ошибки у полей из `error.fields`; 500: «повторите позже». Введённые данные сохраняются | EGO-05 |
| AC-11 | Must | Любой запрос с исходом `match` или `no_match` | В таблице `requests` запись с `request_id`, полями, `comment`, исходом и списком `rule_id` | ROD-05 |
| AC-12 | Must | Валидный POST /api/v1/feedback | 201, `feedback_id`; в таблице `feedback` запись с `request_id` и `rule_id` | ROD-05 |
| AC-13 | Must | Отзыв с неизвестным `request_id`, `rule_id` не из этого запроса, без `applied_value` при `other_value` или без `clarity` | 400 `validation_error`, запись не создаётся | ROD-05 |
| AC-14 | Must | Пилот открыл форму отзыва под карточкой или по сохранённой ссылке | Условные вопросы показываются по логике ALE-04; ID правила пилот не вводит; после отправки — «Спасибо, отзыв сохранён», повторная отправка заблокирована | EGO-05 |
| AC-15 | Should | В базе на момент приёмки | Не меньше 5 разрешённых правил (FED-05) и 15 параметров (FED-02); у каждого правила заполнены `symptom_type`, `corner_phase`, `applicability`; `parameter` совпадает со словарём VAR-02 | Ручная сверка |
| AC-16 | Should | Перебрать все сочетания тип × фаза (6 штук) на одной трассе | Каждое разрешённое правило возвращается хотя бы в одном сочетании; сочетания без правил записаны как пробел для Фёдора | Ручная проверка |
| AC-17 | Should | Новый участник команды идёт по README (ROD-06) | Backend запускается, `/docs` открывается, pytest проходит без устных подсказок | Ручная проверка |

**Про AC-05 и AC-13.** FastAPI по умолчанию отвечает на ошибки валидации кодом 422 и другим форматом тела. Чтобы соответствовать контракту, Родиону нужен собственный обработчик для обоих POST, который вернёт 400.

## Тестовые запросы и границы приёмки

Набор для ROD-05 и EGO-05. Значения `car`, `track` и правила подставить из FED-02 и VAR-04, когда они будут готовы; во всех примерах валидный `comment`, если не сказано иное.

| Критерий | Запрос | Ожидаемый исход |
| --- | --- | --- |
| AC-02 | `oversteer` + `exit` + трасса из `applicability` правила R-001 | `match`, R-001 |
| AC-03 | сочетание, под которое нет правил (например, `understeer` + `mid`, если такого нет) | `no_match` + `request_id` |
| AC-04 | сочетание тестового правила со статусом «не проверено» (фикстура pytest) | `no_match` |
| AC-05 | без `corner_phase`; `symptom_type: "loose"`; `comment: "ab"`; `comment` из 501 символа; `track` не из списка | 400 `validation_error` |
| AC-06 | валидный запрос при подменённой недоступной базе | 500 `internal_error` |
| AC-12 | отзыв: `request_id` из AC-02, `rule_id: R-001`, `applied: as_written`, `symptom_result: weaker`, `new_problem: false`, `keep_change: yes`, `clarity: 4` | 201 |
| AC-13 | случайный `request_id`; `rule_id: R-999`; `applied: other_value` без `applied_value`; без `clarity` | 400 `validation_error` |

**Риск.** Комментарий в поиске не участвует. Если пилот выберет не тот тип или фазу, он получит не тот совет, а текст комментария этого не исправит. Понятные подписи на кнопках («зад срывает», «мордой мимо») снижают риск, а расхождения между комментарием и выбранными полями стоит смотреть на пилоте ALE-05.

**Не входит в приёмку спринта 1:**

- доля советов, которые действительно помогли в симуляторе, — это метрики KIR-04 и пилот ALE-05;
- время ответа и нагрузка — требований в источниках нет;
- авторизация, несколько машин, загрузка .sto, аналитика отзывов в интерфейсе — вне границ MVP.
